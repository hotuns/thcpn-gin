# LoRaWAN V2 观测统计接口需求

用于原位生态云用户总览。上游已于 2026-11-03 发布该接口；平台按本文契约调用，成功字段位于既有 `AppResponse.payload`。完整上游实现说明位于 LoRaWAN 服务端的 `apps/docs/observation-statistics.md`。

## 最小可接入版本

新增 `GET /device/{gateway_sn}/node/{node_index}/statistics`，沿用现有认证和节点位置标识。主键是网关 SN + 节点序号，历史统计不随当前物理节点更换而自动清空。

| 参数 | 类型 | 语义 |
| --- | --- | --- |
| start_at | Unix 秒，必填 | 每日趋势开始时间 |
| end_at | Unix 秒，必填 | 每日趋势及累计统计的截止时间 |
| observation_start_at | Unix 秒，可选 | 正式观测起点；省略表示查询该位置全部保留历史 |
| timezone | IANA 时区，默认 Asia/Shanghai | 每日分桶时区；第一版仅支持 Asia/Shanghai 即可，其他值明确报错 |

趋势最大支持 31 天。所有窗口左闭右开：`[start_at, end_at)`。累计窗口为 `[observation_start_at, end_at)`，**累计不能被 start_at 截成近 7/30 天**。正式观测起点晚于趋势起点时，趋势也应用正式观测起点。起点在截止时间之后时，返回空统计；非法趋势范围返回 400。

以下是返回结构示例，数字仅用于说明字段：

```json
{
  "gateway_sn": "example-gateway",
  "node_index": 1,
  "timezone": "Asia/Shanghai",
  "generated_at": "2026-11-03T04:00:02Z",
  "as_of": "2026-11-03T04:00:00Z",
  "count_unit": "sample_record",
  "complete": true,
  "records": {
    "total": 125430,
    "first_at": "2025-01-01T00:00:00Z",
    "last_at": "2026-11-03T03:58:00Z",
    "daily": [
      {"date": "2026-10-28", "count": 240},
      {"date": "2026-10-29", "count": 240},
      {"date": "2026-10-30", "count": 240},
      {"date": "2026-10-31", "count": 0},
      {"date": "2026-11-01", "count": 240},
      {"date": "2026-11-02", "count": 240},
      {"date": "2026-11-03", "count": 120}
    ]
  },
  "images": {
    "supported": false,
    "total": null,
    "daily": null
  }
}
```

- `total` 为 int64 非负计数。一份有效采样内容计一条，无论内含多少指标；不统计网关状态、配置、日志或派生计算结果。
- 有效性过滤与普通 `/data`、`/latest` 查询一致：`ts` 和 `created_at` 均须为标量 BSON Date，数组中含 Date 也不计。
- 三个查询接口统一按完整采样内容去重，只忽略根 `_id`、根 `created_at` 和 `meta.gateway_id`，并规范根/meta 字段顺序；保留毫秒时间、配置和所有采样内容差异。同时间不同内容或配置仍分别计数，不按 `DISTINCT ts` 合并。仅查询聚合去重，不修改或删除原始文档。
- `daily` 按日期升序，包含趋势范围内所有当地日期（首末天可为部分日）。真正无记录的日期为 0。空数据时 total=0、first_at/last_at=null，daily 仍补齐零值。
- first_at/last_at 对应累计统计所覆盖的有效观测，不受趋势 start_at 限制；未来时间不越过 end_at。
- `as_of` 表示这份统计实际覆盖的截止时刻，`generated_at` 表示统计响应/快照生成时刻；若有缓存，不能把当前请求时刻冒充统计快照时间。返回 complete=true 应代表声明范围已完整统计，不允许分页截断后仍标为完整。
- 如果物理保留策略已删除旧数据，累计表示当前仍保留、可查询的数据；如有 history_start_at，可额外返回以解释历史覆盖范围。

## 执行与错误要求

在 MongoDB 端按网关、节点、有效 ts 等同一过滤条件聚合，用 `$count` / `$group` / `$min` / `$max` 或等价实现；不要在 API 中逐页拉取全部历史再计数。累计和每日桶最好在同一读快照/聚合中取得，避免上报并发时互相矛盾。

索引需根据实际 collection 和查询条件评估，至少覆盖网关、节点和时间筛选；不要为每次首页访问全表无条件扫描。可缓存统计，但缓存键必须包含网关、节点、正式观测起点、时区、趋势区间和统计口径版本。

- 不存在的位置：404；已存在但没有数据：200 + 确定的零值。
- 非法时间/节点/时区：400。
- 数据库故障或超时：5xx，不能返回 200 + 0。
- 如果实现了部分结果，必须 complete=false，缺失的值用 null，并给出稳定错误码；第一版也可直接返回错误，避免引入复杂部分响应。
- 源端只读，不更改设备配置或触发采集。

## 后续扩展（不是最小版本的前置条件）

### 图片统计

若节点确实存储采集图片，返回 supported=true、累计张数和按日张数。只计有效非空图片对象引用，排除设备头像、缩略图、同一图片的重复配置别名。明确多图片字段与同一条记录内重复引用的去重规则。没有该能力返回 supported=false + null，不能填 0 表示没有图片。

### 更新计划

可额外返回设备实际报告或已确认生效的采集和上传计划、计划来源及更新时间。只在全天均匀周期可以明确计算时提供 expected_interval_seconds；应考虑采集和上传两者较慢的节奏。非均匀、仅白天或尚未确认生效的计划保持 unknown，不能将 wait_time 或设备启用状态当采样周期。

### 多节点批量

若单节点接口落地后请求量较大，可再加网关批量接口，一次指定若干 node_index。每个节点独立返回成功/失败，汇总方不会把网关状态记录和节点采样重复相加。单节点版本是先行接入标准，不必等批量版本。

## 验收用例

1. 10条采样文档，每条含3个数值指标：累计为10，不是30。
2. 同一位置同时间的两条记录，配置或采样内容不同则计2；仅数据库 ID、入库时间、meta.gateway_id 或根/meta 字段顺序不同则合并为1。
3. 混有非BSON DateTime或不可正常返回的文档：计数与可查询有效记录一致，不照搬旧pagination.total_count。
4. 北京时间午夜记录只进入新一天；恰好end_at的记录不计入本次。
5. 切换7天和30天趋势，保持相同end_at、正式观测起点时累计不变。
6. 正式观测起点之前的记录不计入累计/每日/首末时间；不把测试数据加进正式观测。
7. 某天无数据为0；数据库故障为错误，二者能被客户端区分。
8. 缓存命中时as_of保持真实旧截止时刻，不能仅更新generated_at伪装实时。
9. 当前物理节点更换后仍按原网关+节点位置查询历史，不按新节点SN错误清空或重复累计。
10. 累计超出旧分页上限仍准确；请求不会产生与历史条数成正比的API分页调用。
