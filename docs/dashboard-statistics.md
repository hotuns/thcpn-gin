# 用户观测总览

总览通过 `GET /api/v1/workspaces/{workspace_id}/dashboard?days=7|30` 读取当前工作区可见的观测统计。返回结构以 [OpenAPI](openapi.yaml) 为准，客户端类型由该文件生成。

## 统计口径

- 一条有效原始采样记录计一次，不乘以指标数量，不把数据集、导出或派生计算结果加进累计。不同记录可以有相同采样时间。
- 图片单独统计有效对象引用；同一条图片记录内重复引用只计一次。设备头像不属于观测图片。
- 累计覆盖正式观测起点至统计截止时刻的可查询历史。7/30 天仅改变趋势，不改变累计窗口。
- 日期桶固定为 Asia/Shanghai，窗口左闭右开。午夜归入新一天。
- `null` 表示无法确认，0 表示已确认没有记录。`complete=false` 的统计显示覆盖范围，不能解释为完整工作区总量。
- 设备更新状态需要真实观测时间及明确的全天均匀采集、上传计划。延迟阈值取两种计划较慢周期的两倍，且不少于 5 分钟；缺少计划或源统计时保持未知。

## 当前数据源覆盖

| 数据源 | 记录 | 图片 | 限制 |
| --- | --- | --- | --- |
| THCPN | 原始 data 行累计、每日、首末时间 | 历史配置解析的有效图片引用累计、每日 | 缺失历史图片配置时，相应图片统计未知；不使用遥测接口的分表数量上限 |
| Carbon | 现有业务可查询的 device_data_next 月表原始 data 行 | 未知 | 不叠加旧 device_data 或 carbon_flux；不代表已证明历史迁移完整 |
| LoRaWAN V2 | 未知 | 未知 | 当前接口不能提供可靠聚合，不遍历历史分页；接口需求见下文 |

THCPN 独立设备按 2026-07-01 北京时间的存储切换分区；网关及其独立节点使用索引分表。Carbon 应用各节点的正式观测起点。LoRaWAN 含节点观测的网关保留在统计覆盖范围内，纯状态网关排除。

LoRaWAN 待实现接口：[LoRaWAN V2 观测统计接口需求](lorawan-v2-observation-statistics.md)。本版本不调用尚未提供的上游接口。

## 权限与刷新

每次请求检查工作区、设备，以及记录历史和媒体归档权限；活动告警仅统计该工作区中获准读取的设备。缓存保存单个来源的结果，不保存可跨用户复用的工作区汇总。

源结果缓存 5 分钟，后台最多并发 4 个源查询，单次刷新共享 1 分钟截止时间。首屏冷缓存返回未知并建议 5 秒刷新，通常建议 30 秒刷新。失败保留旧结果但标为不完整；跨日旧快照不能作为新一天已确认的零值。`statistics_updated_at` 是所展示统计中最旧的源快照时间，不是页面请求时间。

绑定、父设备关系、LoRaWAN 节点安装关系或正式观测起点变化会改变缓存版本。Redis 锁合并多 API 进程刷新；本地缓存有容量限制。接口返回 `Cache-Control: private, no-store`。

## 页面

核心统计为累计观测记录、累计图片、今日新增记录/图片和正常更新设备。趋势支持 7/30 天、记录/图片、柱图/数据表；触控、鼠标和键盘均可读取日期数值。需要关注列表跳转到对应设备，告警入口打开预警中心。切换工作区不会保留另一工作区的旧数值。

## 验证边界

- 聚合、权限撤回、冷热缓存、跨日和范围切换有 Go 单元测试；缓存并发通过 race 检查。
- PostgreSQL 仓库测试创建独立临时数据库，验证缓存版本和告警范围，不修改业务库记录。
- 数据源 SQL 使用网络隔离 driver 测试；THCPN 图片去重另提供可选 MySQL 引擎测试。未执行真实 MySQL 源的 SQL 集成测试。
- 页面使用严格 API 请求拦截进行手机/桌面、中英文/暗色、范围切换、空数据、失败重试和工作区隔离验收。Fixture 仅在测试中使用。
- 浏览器 fixture 验收不能代替部署后真实来源计数核对。
